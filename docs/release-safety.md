# Выпуск без автоматического изменения схемы БД

Серверный helper исторически вызывает `npm run db:push`. Этот npm-скрипт должен быть заменён на `tsx script/check-release-db.ts`: это совместимый вход для read-only проверки и резервной копии, НЕ вызов Drizzle push. Нельзя выпускать ветку без обновлённого package.json и lockfile.

Проверка требует доступности всех колонок 34 таблиц из полного `shared/database-schema.ts` в транзакции READ ONLY. Используются SELECT ... LIMIT 0; пользовательские записи не возвращаются в журнал. Это проверка совместимости чтения, не доказательство эквивалентности типов, индексов, ограничений и схемы целиком. Автоматические ALTER/DROP/DELETE/TRUNCATE не выполняются. При несовместимости релиз останавливается; необходимые миграции следует согласовать отдельно.

После проверки pg_dump создаёт полную custom-format копию одной БД в `$HOME/.local/state/govza/backups` (или GOVZA_BACKUP_DIR) вне релиза и web-root. Каталог 0700, архив и manifest 0600. Строка подключения передаётся через окружение дочернего процесса и не выводится в argv/журнал. Любая ошибка или предупреждение pg_dump останавливает выпуск. Архив проверяется через pg_restore --list и полное декодирование SQL в /dev/null без подключения к БД; записываются размер и SHA-256. Старые копии не удаляются и в GitHub не загружаются.

CI создаёт отдельные localhost *_test базы, проверяет отказ на отсутствующей колонке, сохранность посторонней таблицы, приватность архивов, ошибки резервирования и восстановление тестовой копии в новую пустую БД. Производственная БД не восстанавливается и не очищается. Проверка архива production не равна полной репетиции восстановления production.

Прямой drizzle-kit push допускается только интерактивно с NODE_ENV=development для localhost БД с суффиксом _dev. Полный список схем включает авторазборы/магазины и остальные runtime-таблицы, ранее отсутствовавшие в drizzle.config.ts.

## Границы
Копия на том же сервере не заменяет off-site backup, PITR и резервирование файлов загрузок, глобальных ролей, сертификатов и конфигурации. Шифрование архива и удалённое хранилище здесь не объявляются настроенными. Политика хранения и мониторинг свободного диска нужны отдельно. Публикация также требует рабочего HTTPS, действующей проверки admin на сервере и прохождения CI/браузерной приёмки. Обходы проверок и --force недопустимы.
