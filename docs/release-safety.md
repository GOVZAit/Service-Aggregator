# Публикация без автоматического удаления таблиц

Серверный helper исторически вызывает `npm run db:push`. Этот npm-скрипт теперь запускает `tsx script/check-release-db.ts`: read-only проверку совместимости и резервирование, а НЕ Drizzle push. Дополнительный явный alias — `npm run db:check-release`.

Проверка читает доступность колонок 34 ORM-таблиц из полного `shared/database-schema.ts` в транзакции READ ONLY. SELECT ... LIMIT 0 не возвращает пользовательские записи в журнал. Это проверка существования/совместимости чтения, не доказательство эквивалентности типов, индексов, ограничений и всей схемы. ALTER/DROP/DELETE/TRUNCATE этот шаг не выполняет. При несовместимости выпуск останавливается; миграции согласуются отдельно. Существующие startup ensure/seed-функции приложения — отдельный механизм и здесь не объявляются отсутствующими.

Затем pg_dump создаёт полную custom-format копию одной БД в `$HOME/.local/state/govza/backups` или GOVZA_BACKUP_DIR вне релиза/web-root. Каталог 0700, архив/manifest 0600. Параметры libpq передаются отдельно; пароль находится во временном приватном PGPASSFILE, удаляемом после попытки. Полный DATABASE_URL и пароли не попадают в argv, журнал или артефакты GitHub. Неподдерживаемые/неоднозначные параметры подключения отклоняются, а не молча игнорируются.

Любая ошибка или предупреждение pg_dump останавливает выпуск. Проверяются формат PGDMP, список содержимого и полное локальное декодирование через pg_restore --file=/dev/null без подключения к БД. Manifest содержит размер, дату и SHA-256. Старые копии не удаляются; архивы не скачиваются в GitHub и не публикуются.

CI использует две изначально пустые localhost *_test БД в одноразовых PostgreSQL-сервисах. Проверяется сохранность дополнительных таблиц, отказ при несовместимости через симуляцию, закрытые права файлов, восстановление синтетических данных в второй пустой сервис, обработка ошибок и запрет unattended push. Production БД тесты не используют и не восстанавливают. Проверка архива production не равна репетиции восстановления всей production-системы.

## HTTPS и граница прокси
В production приложение слушает только 127.0.0.1; доверие к X-Forwarded-* ограничено loopback-прокси. Разрешённый локальный Nginx должен перезаписывать X-Forwarded-Proto фактической схемой соединения. Серверный контроль admin/сессии/HTTPS сохранён. Временный выпуск сертификата выполнен штатным helper `issue-govza-certificate`.

## Проверки публикации
Workflow допускает только main, требует npm audit без известных уязвимостей, типизацию/build/smoke, проверяет безопасный db:push alias и HTTPS до отправки релиза. После активации требуются сообщение успешного backup-gate, байтовое совпадение опубликованных CSS/JS/Service Worker со сборкой, HTTPS всех основных страниц, HTTP→HTTPS и 401/no-store для анонимных административных GET. Публичные ID автокаталога сравниваются до/после. Это не побайтовое сравнение БД и не тест авторизованных действий реального администратора.

## Оставшиеся ограничения
Копия на одном сервере не заменяет off-site backup, PITR, резервирование файлов загрузок, глобальных ролей, сертификатов и конфигурации. Шифрование архивов/удалённое хранилище здесь не объявляются настроенными. Нужны отдельная политика хранения и мониторинг диска. Нулевой npm audit не является полным аудитом безопасности или подтверждением актуальности системных пакетов и Node.js на production-сервере. Проверка на физических телефонах и реальным администратором остаётся отдельной приёмкой.
