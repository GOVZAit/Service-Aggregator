# Избранное, история и повторная запись

Изменения развивают существующие DB-избранное и форму повторного заказа, не создавая параллельные сущности.

## Пользовательские сценарии

- `/saved`: избранные мастера. Сердечко в каталоге, профиле и списке использует общий запрос с ключом аккаунта. Изменение оптимистическое, повторный клик блокируется до ответа, ошибка откатывает только изменённый профиль. Фокус окна/периодическое обновление подтягивают изменения другого устройства. Удалённый мастер отображается как недоступный с возможностью убрать его из списка.
- `/saved?tab=recent`: последние 30 разных просмотренных профилей за последние 90 дней. Просмотр фиксируется только для вошедшего клиента. Повторное открытие перемещает профиль вверх. Очистка требует подтверждения и не удаляет избранное/заказы. Гостевые просмотры не записываются и не импортируются.
- «Повторить заказ»: из завершённого заказа берутся услуга, адрес и комментарий. Дата и время выбираются заново. Старую цену, статус, переписку и отзыв не копируем. Отсутствующая услуга не заменяется автоматически. Сервер повторно проверяет мастера, услугу, будущую дату, указанное окно и цену. Расхождения возвращают 409, форма обновляет данные и требует нового подтверждения. Новый заказ получает статус `pending`.
- «Свободен сегодня»: только явная запись `available` в календаре мастера с корректным незавершённым окном. Онлайн-статус и рабочие часы сами по себе не дают этой отметки. Дата и время едины для сервиса: Europe/Moscow. Незаполненное расписание разрешает отправить запрос на согласование, но не даёт отметку свободного времени. Это не система резервирования: мастер подтверждает заявку, интервал не блокируется автоматически.
- Поиск: имя, компания, категория, услуги, город, район и описание; ё/е, регистр, начало слова, ограниченные синонимы и одна опечатка в длинных словах. Все слова запроса должны совпасть; выдача не расширяется скрытно. Это детерминированный поиск по текущему каталогу, не AI/семантический поиск и не геолокационный поиск рядом с устройством.
- Фильтры: общая функция для мобильной панели, настольной колонки и счётчика. Цена, рейтинг, отзывы, выполненные заказы, доступность, проверка, сертификат, тип исполнителя/профиля, район. Неуказанная цена не равна нулю. Сортировки по цене, рейтингу, отзывам, заказам, расстоянию из профиля и соответствию запросу. URL сохраняет условия; локальное восстановление раздельно по аккаунтам.

## Данные и выпуск

`ensureClientMemoryTables` после существующей инициализации расписания создаёт новую таблицу `user_master_views`, уникальность `(user_id, master_id)` и индексы. Старые таблицы/записи не удаляются. Инициализация повторяемая. FK на `auth_users` удаляет историю при удалении аккаунта.

Ограничение 30 записей и очистка сериализуются транзакционной advisory-блокировкой на аккаунт. Старые записи отсекаются при чтении; физическая очистка старше 90 дней выполняется при следующей записи этого пользователя. Это не глобальная ежедневная политика удаления.

Private API не кэшируется HTTP; запросы привязаны к текущей сессии и sessionVersion, ID пользователя из тела не принимается. Новые функции истории доступны только клиентам. Скрытые/удалённые профили не возвращаются в историю.

Перед выпуском нужны резервная копия production БД и обычный процесс review/merge/deploy. Изменения тестируются в отдельной ветке; публикация PR сама по себе сайт не обновляет.

## Проверки

```
npm run check
npm run test:product
npm run build
npm run smoke:build
NODE_ENV=test DATABASE_URL=postgresql://postgres:test@localhost:5432/govza_test npm run test:product:db
```

DB-тест допускает только localhost и БД с суффиксом `_test`. Использует изолированную временную схему, реальный PostgreSQL для избранного, истории и расписания; аккаунты/профили и создание заказа — контролируемые фикстуры. CI создаёт отдельный PostgreSQL service, production secrets не нужны.

Ручная приёмка перед production: телефон 390px, планшет 768px и desktop 1440px; два аккаунта; два устройства одного аккаунта; удалённый мастер; очистка истории; быстрое изменение разных сердечек при одном отказе сети; цена/расписание изменились при открытой форме; переход за полночь МСК; повтор из завершённого заказа с удалённой услугой. Проверить фокус/закрытие диалога клавиатурой и прокрутку панели фильтров.
