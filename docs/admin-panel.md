# Панель администратора GOVZA

Адрес: `/admin`. Для входа используется существующая авторизация GOVZA; нужен аккаунт с сохранённой в БД ролью `admin`. Публичная регистрация не должна назначать эту роль. Панель не создаёт первого администратора, не показывает внутренний ключ и не меняет права аккаунтов.

## Экраны
- Обзор: реальные серверные значения профилей, ожидающих проверок, пользователей и скрытых профилей.
- Мастера и организации: поиск, статус и видимость, создание, редактирование основных полей и выбор категорий по названиям. Данные не удаляются при скрытии.
- Проверка документов: очередь по статусу, просмотр изображений, решение и обязательная причина отклонения. Решение использует существующие серверные маршруты и журнал событий.
- Врачи и городские службы: добавление, обычные формы, скрытие; поля, не представленные в форме, сохраняются. Рейтинг и число отзывов врача не переписываются при редактировании контактов.
- Автозапчасти: автомагазины/авторазборы, контакты, адрес, типы автомобилей, марки, условия, видимость; привязка аккаунта владельца с отдельным подтверждением.
- Категории: создание и редактирование названия, значка, эмодзи и цвета.
- Пользователи: только просмотр контактов, даты регистрации и ролей. Поиск и постраничная выдача на сервере, максимум 50 строк на запрос. Пароли, хеши, токены и версии сессий не выбираются SQL-запросом и не отдаются браузеру.
- Импорт: конфигурация без ключей, ручной запуск уже настроенных источников и последние 30 результатов.
- Журнал: последние 200 событий существующего аудита; поиск внутри этой выборки. Из панели нельзя исправить или удалить журнал.

## Взаимодействие и ограничения
На широком экране постоянное левое меню. На телефоне меню открывается по кнопке; формы используют общий ResponsivePanel. Кнопки сохранения закреплены снизу. Закрытие изменённой формы требует подтверждения, ошибки не стирают ввод. При переходах браузером назад/вперёд восстанавливается раздел по URL. Перезагрузка с несохранённой формой вызывает стандартное предупреждение браузера; сама форма не сохраняется в localStorage.

Нет новых кнопок удаления аккаунтов, смены ролей, рассылок или финансовых действий. Панель не получает доступ к приватной переписке и заказам. Конкурентные изменения одного объекта несколькими администраторами остаются ограничением существующих API (optimistic locking не добавлялся). Ограничения старых схем не обходятся: очистка существующего описания исполнителя и URL магазина не поддерживается — форма сообщает об этом, а не имитирует сохранение.

## Безопасность
Общий серверный `authenticatedAdmin` использует актуальный аккаунт из БД и проверяет роль и версию сессии на каждом запросе. Отсутствующая/отозванная сессия — 401; неверная роль — 403; ошибка проверки — закрытый доступ. Изменяющие запросы требуют `X-Govza-Admin: 1` и same-origin Origin/Referer либо Fetch Metadata, cross-site/same-site запросы блокируются. Существующий CORS не расширялся. Ответы /api/admin — `Cache-Control: no-store, private`; данные не складываются в локальное хранилище. Клиент удаляет административный кеш при завершении панели и прекращает отображение данных после 401/403.

В production администрирование по HTTP запрещено и на клиенте, и на сервере. В локальных тестах используется NODE_ENV=test. За reverse proxy нужны корректные Host/X-Forwarded-Proto; доступ напрямую к backend должен быть ограничен. Проверку нельзя отключать ради неработающего HTTPS.

Справочные требования: OWASP Authorization Cheat Sheet (Validate permissions on every request) и CSRF Prevention Cheat Sheet (custom headers, same-origin verification, Fetch Metadata).

## Публикация
Изменения подготовлены в отдельной ветке. Настройки TLS, deploy workflow и `drizzle.config.ts` в этой задаче не меняются. До публикации необходимо устранить ранее найденное предупреждение разрушительного `db:push`, настроить и проверить HTTPS и сделать резервную копию БД. Выполнять `db:push --force` запрещено в рамках этой задачи. Роли существующих пользователей и production БД не изменялись.

## Проверки
`npx tsx script/test-admin-access.ts` — чистые проверки контроля доступа без БД.
`NODE_ENV=test DATABASE_URL=postgresql://...@127.0.0.1:5432/..._test npx tsx script/test-admin-users-db.ts` — отдельная временная схема в тестовом PostgreSQL. Скрипт отказывается от нелокального адреса и базы без суффикса `_test`.
`PLAYWRIGHT_MODULE=/path/to/playwright UI_BROWSER=chromium UI_REPORT=/tmp/admin-ui node script/test-admin-ui.cjs` — собранный frontend, локальный сервер и HTTP-фикстуры. Внешние запросы блокируются, реальные пользователи и production не используются. Аналогичный запуск WebKit доступен в CI. Проверка физического iPhone/Android, экранной клавиатуры, PWA и полный аудит безопасности остаются отдельной приёмкой.
