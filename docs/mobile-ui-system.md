# GOVZA: единая мобильная система интерфейса

## Область
Общий каркас внедрён для главного каталога мастеров, врачей, автозапчастей, «Ещё» и клиентского профиля. Заявка мастерам и фильтры используют общую панель. Вложенные рабочие кабинеты и все исторические формы не объявляются полностью переработанными в этом проходе.

## Компоненты и правила
- `DirectoryFrame`: общий логотип, навигация, заголовок и город. Не собирать отдельную шапку через отрицательные отступы.
- `DirectorySearch`: поле 52 px, 16 px текст, одинаковая кнопка фильтров. Закрепляется только поиск, не вся верхняя часть страницы.
- `DirectoryChip` и `DirectoryResults`: одинаковое выделение выбора, счётчик, переключение списка/карты. Основные интерактивные зоны не меньше 44 px.
- `ResponsivePanel`: на ширине менее 720 CSS px — снизу, иначе справа шириной 420 px. Прокручивается тело, а не кнопки подтверждения. Используются Radix Dialog, Escape, удержание и возврат фокуса. Выделение текста и масштабирование не блокируются панелью.
- `directory-grid`: одна колонка, с 720 px — две, с 1120 px — три. `align-items: start`; карточки не растягиваются до высоты соседа.
- Основные действия 48 px. Одна цветовая роль основной кнопки; второстепенные действия нейтральные. Палитра и размеры в `client/src/styles/directory.css`.
- Мобильная нижняя навигация содержит пять разделов без горизонтальной прокрутки. С 1024 px на основных экранах используется верхняя навигация.

## Состояния
Фильтры имеют отдельный черновик: закрытие не применяет изменения. «Применить» сохраняет выбор. Поиск и город не сбрасываются без явного действия. Счётчик не подменяет реальные ответы API. Ошибки отправки не стирают форму; повторная отправка выполняется явным нажатием. Переходы назад между шагами заявки сохраняют поля.

Не добавлять несуществующие гарантии, сроки приезда, сгенерированные отзывы, сообщения от имени исполнителя или имитацию оплаты. Онлайн-статус не равен доступному времени. Указанная цена — данные профиля, не обещание конечной суммы.

## Автоматическая проверка
`Directory UI acceptance` запускается для PR в Chromium и WebKit. Проверяется production frontend с изолированными HTTP-фикстурами; production БД и API не используются. Разрешены только локальный стенд и существующие публичные шрифты Google. Сторонние изображения блокируются: проверяется также отображение инициалов при недоступном фото.

Размеры: 320×720, 390×844, 430×932, 768×1024, 1024×768, 1440×1000. Дополнительно панели на 844×390. Проверяются отсутствие горизонтального переполнения документа, высота поиска, нижняя навигация при прокрутке, границы панелей, неподвижные кнопки, Tab/Escape/возврат фокуса, отмена черновиков, избранное и неудачная/повторная отправка заявки. Скриншоты и `results.json` доступны в артефактах workflow.

Локальные команды: `npm run check`, `npm run test:product`, `npm run build`, `npm run smoke:build`. Для UI: сначала `UI_FIXTURES=/tmp/ui.json ./node_modules/.bin/tsx script/directory-ui-fixtures.ts`, затем `UI_FIXTURES=/tmp/ui.json UI_REPORT=/tmp/ui-report UI_BROWSER=chromium PLAYWRIGHT_MODULE=/path/to/playwright node script/test-directory-ui.cjs`.

## До публикации
Просмотреть снимки, проверить iPhone Safari и Android Chrome с настоящей экранной клавиатурой, системным увеличением текста, вырезами экрана, поворотом, установленным PWA и реальными фотографиями. Проверить вход двумя аккаунтами и реальные ответы API в разрешённом тестовом окружении. Автоматический WebKit на Linux не равен физическому iPhone; тестовые HTTP-ответы не подтверждают доставку сообщений реальному врачу или платёжную интеграцию.

В этом проходе версии runtime-зависимостей и lockfile не изменялись. Предупреждения `npm ci` о 18 уязвимостях, включая 13 high, требуют отдельного разбора и не считаются устранёнными редизайном.
